# P2 Login and Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:test-driven-development. Tasks A and B run in parallel worktrees; Task C integrates. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Google sign-in with users provisioned by `sub`, an HttpOnly/Secure/Lax session cookie (4 h), SPA CSRF, security headers, 401/403 ProblemDetails for `/api/**`, and a 60 req/min per-user limit (milestone M2 minus the live Google login, which waits for secrets).

**Architecture:** Spring Security 7 `oauth2Login` in the one app. An `OAuth2UserService` adapter delegates to Spring's `OidcUserService`, then `OidcUserProvisioningService` finds/creates the `app_user` and returns an `AppOidcUser` principal (our user ID + role) stored in the HTTP session. Rate limiting and MDC user ID are plain filters added inside the security chain.

**Tech Stack:** Spring Boot 4.1.1 · Spring Security 7.1.1 · Bucket4j 8.21.0 · Caffeine · MySQL 8.4 Testcontainers.

**Spec:** `docs/plan/04-work-breakdown.md` P2-01…P2-03; `docs/plan/02` §6; D-02, D-10, D-12, D-21; R-C, R-D, R-E; M-04 = 4 h.

## Global Constraints

- Identity only from the session principal (`AppOidcUser` / `CurrentUser.from(Authentication)`); never from headers.
- Unverified email → USER only; never ADMIN, never consumes a TPO assignment (R-C).
- Every TPO/admin decision writes `audit_log` (R-E); consuming a TPO assignment writes one row.
- `/api/**` unauthenticated → 401 `application/problem+json`, never a redirect; wrong role → 403 ProblemDetail.
- CSP exactly: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`.
- Rate limit: 60 requests/min per signed-in user (in-memory Bucket4j); 61st → 429 ProblemDetail `errorCode` `RATE_LIMITED`. No per-IP limit.
- Logging (D-27) unchanged: no emails/names in logs; MDC `userId` only.
- Flyway versions continue from V2: V3 college, V4 app_user, V5 tpo_assignment (one DDL change per file).
- Secrets deferred by the user: Google client ID/secret default to `not-configured`; live sign-in proof is recorded as Not executed.

## Shared contracts (committed before the agents start)

`auth.Role {USER, TPO, ADMIN; authority()}` · `auth.AppOidcUser(UUID userId, Role role, OidcIdToken, OidcUserInfo)` · `auth.CurrentUser(UUID id, Role role)` + `static Optional<CurrentUser> from(Authentication)` · `auth.OidcIdentity(String sub, String email, boolean emailVerified, String name)` · `auth.ProvisionedUser(UUID userId, Role role)` · `auth.MeResponse(UUID userId, String name, String email, Role role, CollegeSummary college, String membershipStatus)` · `college.CollegeSummary(UUID id, String name)` · `offershield.admin.emails` ← `ADMIN_EMAILS`.

## Review Focus

1. A Google account whose email is in `ADMIN_EMAILS` but `email_verified=false` → must stay USER (`OidcUserProvisioningServiceTest.unverifiedEmail_userOnly`, Task A).
2. Email case/whitespace differences (`Admin@X.com ` vs `admin@x.com`) → still match ADMIN/TPO (`verifiedAdminEmail_caseInsensitive_admin`, Task A).
3. `@PreAuthorize` denial inside MVC turning into 500 via the catch-all handler → 403 ProblemDetail (`MethodSecurityTest.wrongRole_403Problem`, Task C).
4. Rate-limit buckets growing without bound → Caffeine cache with expiry (`UserRateLimitFilterTest.twoUsers_separateBuckets` + review).
5. Session fixation on login → Spring's default `changeSessionId` stays on (review; no custom session management).
